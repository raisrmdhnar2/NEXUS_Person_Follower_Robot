
# NEXUS Interface Specification

## 1. Purpose

This document defines the interfaces between NEXUS software modules.

The objective is to establish consistent data structures and communication boundaries before implementation.

The interfaces are divided into:

1. Internal Raspberry Pi interfaces
2. Raspberry Pi ↔ ESP32 interface
3. ESP32 internal interfaces
4. Event interfaces

---

# 2. Interface Design Principles

The following principles apply:

* Modules communicate through defined data structures.
* Modules should not directly modify another module's internal state.
* `target_id` is owned by `TargetManager`.
* Robot state is owned by `StateMachine`.
* Wheel commands are generated by the control layer.
* UART communication is isolated inside `ESP32UART`.
* ESP32 owns actual motor control.
* Safety-critical commands have priority over normal commands.

# 3. Core Data Types

## 3.1 `PersonDetection`

Represents a person detected by the object detector.

```text
PersonDetection
├── bbox
├── confidence
└── class_id
```

### Fields

| Field          | Type              | Description               |
| -------------- | ----------------- | ------------------------- |
| `bbox`       | `[x1,y1,x2,y2]` | Person bounding box       |
| `confidence` | float             | Detection confidence      |
| `class_id`   | int               | Detector class identifier |

---

# 4. `TrackedPerson`

Represents a person maintained by the tracking subsystem.

```text
TrackedPerson
├── track_id
├── bbox
├── center
├── confidence
└── status
```

### Fields

| Field          | Type              | Description                   |
| -------------- | ----------------- | ----------------------------- |
| `track_id`   | int               | Persistent tracking ID        |
| `bbox`       | `[x1,y1,x2,y2]` | Bounding box                  |
| `center`     | `(x,y)`         | Bounding-box center           |
| `confidence` | float             | Tracking/detection confidence |
| `status`     | enum              | Tracking status               |

Possible status:

```text
ACTIVE
LOST
```

---

# 5. `GestureDetection`

Represents a detected hand gesture.

The NEXUS password is the open-palm gesture:

```text
🖐🏻
```

### Fields

| Field            | Type              | Description            |
| ---------------- | ----------------- | ---------------------- |
| `gesture_type` | enum              | Detected gesture       |
| `confidence`   | float             | Recognition confidence |
| `hand_bbox`    | `[x1,y1,x2,y2]` | Hand bounding box      |
| `hand_center`  | `(x,y)`         | Hand center            |

Possible gesture types:

```text
NONE
PASSWORD
OTHER
```

```text
Target
├── track_id
├── bbox
├── center
├── distance
├── visible
└── status
```

### Fields

| Field        | Type              | Description               |

# 14. Center Controller Interface

### Input

```text
target_center_x
image_width
```

### Output

```text
angular_velocity
```

### Interface

```text
compute(target_center_x, image_width)
```

### Equation

$$
e_x=x_c-\frac{W}{2}
$$

Initial proportional controller:

$$
\omega=K_xe_x
$$

The output must be limited to the configured maximum angular velocity.

---

# 15. Distance Controller Interface

### Input

```text
target_distance
desired_distance
```

### Output

```text
linear_velocity
```

### Interface

```text
compute(distance)
```

Distance error:

$$
e_d=D_{person}-D_{target}
$$

Initial behavior:

```text
distance > target distance
    → forward

distance ≈ target distance
    → stop / slow

distance < target distance
    → stop
```

```text

```

```text

├── left_velocity
└── right_velocity
```

```text

```

### Equations

$$

$$

$$

# 19. `WheelCommand`

```text
WheelCommand
├── left_velocity
└── right_velocity
```

### Units

```text

```

The interface must use signed velocity:

```text
positive → forward
negative → backward
zero     → stop
```

# 20. Raspberry Pi ↔ ESP32 Interface

The communication interface transfers wheel commands from Raspberry Pi to ESP32.

Conceptual direction:

```text
Raspberry Pi
    │
    │ WheelCommand
    ▼
   UART
    │
    ▼
  ESP32
```

Feedback:

```text
ESP32
    │
    │ ESP32Status
    ▼
   UART
    │
    ▼
Raspberry Pi
```

---

# 21. Pi → ESP32 Commands

The following logical commands are required:

```text
VELOCITY
STOP
PING
```

### VELOCITY

Contains:

```text
left_velocity
right_velocity
```

### STOP

Commands both motors to stop immediately.

### PING

Checks communication availability.

The exact serial packet syntax is defined separately in `communication_protocol.md`.

# 28. Interface Safety Rules

1. Invalid data must not generate a movement command.
2. Missing target data must not generate a normal follow command.
3. `None`/invalid sensor values must be handled explicitly.
4. Wheel velocities must be saturated before transmission.
5. `STOP` must have higher priority than normal velocity commands.
6. UART timeout must cause the ESP32 to stop the motors.
7. A target ID must never be changed by the Follow Controller.
8. Robot state must not be changed by HMI or Speech modules.

---

# 29. Interface Summary

The primary software contracts are:

```text
Camera
    → Frame

Person Detection
    → PersonDetection[]

Person Tracking
    → TrackedPerson[]

Gesture Recognition
    → GestureDetection

Association
    → person_id

Authentication
    → AuthenticationResult

Target Manager
    → Target

Follow Controller
    → FollowCommand

Differential Drive
    → WheelCommand

UART
    → ESP32

ESP32
    → Motor Actuation
```

These interfaces form the contract between NEXUS modules and should remain stable even if the internal implementation of a module changes.
